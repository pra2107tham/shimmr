How it actually works

From a user's side of the screen

The first ten minutes

Rahul is CTO at a twelve-person startup. He has never heard of us. Here is his whole experience.

Minute 0

He downloads one file. Nothing to install first — no Node, no Python, no Docker. It just runs.

Minute 1

He runs one command. Shimmr finds the editors he already uses and sets them up for him.

$ shimmr init Found Claude Code → configured Found Cursor → configured Restart either one and you're ready.
Minute 3

He points it at his repo. The map builds in well under a minute.

$ shimmr index . Reading ████████████████████ 1,247 files Linking ████████████████████ 8,932 functions Done in 41s. 14,201 connections mapped. Everything stored at ~/.shimmr — nothing was uploaded.
Minute 4

He asks Claude Code the question he always has to answer for new hires. It comes back in about two seconds with a file, a line number, and the four places that call it — having read four functions instead of thirty files.

Day 7

Curious what it has been doing, he checks. This is the screenshot he sends his co-founder.

$ shimmr stats This week 342 questions answered from the map search_graph 118 ████████████████ get_code_snippet 87 ████████████ trace_path 64 █████████ get_architecture 41 █████ semantic_query 32 ████ Tokens saved ~2.1M (how this is calculated: shimmr stats --method) Left your laptop 0 bytes
Week 3

Two more engineers want it. He invites them from his account and they skip setup entirely — this is the first moment he needs us rather than a repo he could have cloned.

Later

He connects GitHub. Now when the agent looks at a strange-looking function, it can also see the PR that introduced it and the issue that asked for it — so it stops suggesting changes that were already tried and reverted. This is the part he pays for.

The business model

Local is free. Crossing the boundary is paid.

Local code indexing is a solved, commoditised capability — so we don't build a business on charging for it. We charge for the one thing nobody can get anywhere else: their own team's context, wired into their agent, on their own infrastructure.

Free, permanently
Everything local
  • The full code map, all 16 tools, semantic search
  • One-command setup for every editor you use
  • The local dashboard and usage log
  • No account required, no seat limit, no expiry
Paid
Everything connected
  • GitHub issues and PRs as agent context
  • OpenHands and other agent runtimes
  • Scheduled and triggered automations
  • Team accounts, shared setup, seats
Why this line holds

The left column is commodity — several tools do it, and a determined engineer can assemble it for free in an afternoon. Charging for it would be renting out something that isn't scarce. Nobody can assemble “my team's GitHub history, wired into my agent, on our own infrastructure.” The free half drives adoption honestly; the paid half is genuinely ours to sell.
